# Проверка безопасности по модулям

## Запуск из PowerShell

Текст «Создай workflow…» является запросом для Codex, а не командой Windows.
Из корня репозитория выполняется команда:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/security-check.ps1
```

`ExecutionPolicy Bypass` действует только на этот процесс PowerShell и позволяет
запустить проверенный локальный скрипт при запрете `.ps1`; постоянная политика не меняется.

Требуются Python 3.10+, Git, `rg` и авторизованный Codex CLI с поддержкой
`exec --ephemeral --sandbox read-only --output-schema`. Модель берётся из текущей
конфигурации CLI. Запуск использует аккаунт Codex и его лимиты. Справка команд
проверена через установленный `codex exec --help`; режимы описаны в
[официальной документации](https://learn.chatgpt.com/docs/non-interactive-mode).
Агентам запрещены сетевые инструменты и внешние приложения; собственное соединение
Codex с моделью необходимо для анализа исходников. Пароли, vault-файлы, ключи,
signing material и реальные пользовательские данные не входят в область чтения.

## Этапы

1. `prepare` перечисляет исходники активной `electron-app/`, проверяет, что каждый
   текстовый файл назначен ровно одному модулю, и фиксирует SHA-256 исходников
   и политик. Неназначенный/дважды назначенный файл останавливает подготовку.
2. Для каждого модуля из [modules.json](../security-check/modules.json) запускается
   ровно один новый `codex exec --ephemeral`. Повторное использование истории
   и делегирование отключены. CLI выполняет модули последовательно, поэтому
   не зависит от числа доступных одновременных сессий.
3. Каждый агент возвращает JSON по общей схеме: модуль, запуск, хеш источников,
   полнота обзора, список просмотренных файлов, находки, контрдоказательства,
   проверенные контроли и ограничения. Каждая находка содержит исходные пути,
   диапазоны строк, факты, предпосылки, путь атаки, ущерб и рекомендации.
   Конкретные локальные исходники зависимостей можно читать для подтверждения вызовов;
   `capture-support` фиксирует их отдельные SHA-256 после получения результатов.
   Они не увеличивают счётчик полностью проверенных модульных файлов.
4. Новый контекст интеграции получает все JSON и независимо проверяет находки
   по исходникам. Для каждого кандидата обязательны решение `confirmed`,
   `rejected`, `unresolved` или `duplicate` и доказательства. Объединяются только
   нарушения одного контроля с одинаковым исправлением; дополнительные пути сохраняются.
5. Python проверяет структуру, идентичность запуска, хеши, покрытие и диапазоны
   строк. Он не выполняет текст агентов. Создаются `combined.json` и
   **`security_check_result.md`** в корне репозитория. Пустой/отсутствующий ответ,
   изменённый исходник или недействительный путь не превращаются в успешную проверку.

Схема подтверждает структуру данных и существование строк; семантическую правильность
выводов проверяет контекст интеграции. Это статический обзор, а не доказательство
отсутствия уязвимостей. Доступ к исходникам у агентов общий и read-only; изоляция
контекста не является отдельной VM или жёстким ограничением чтения по модулю.

## Область и политика

| Модуль | Область |
|---|---|
| vault-codec | Криптография, формат, валидация документов и общие контракты |
| vault-storage | Файлы, атомарное сохранение, конфликты, блокировки и ключи сессий |
| electron-boundary | Main/preload, IPC, CSP, протокол, захват экрана и clipboard |
| ssh-terminal | SSH, проверка ключа хоста, алгоритмы и поток терминала |
| hibp | Согласие, приватность запросов и разбор HIBP |
| renderer | Vue, xterm, жизненный цикл секретов и тестовые UI-стенды |
| build-release | Зависимости/lockfile, сборка, упаковка и подпись |

Исключены старое .NET/WPF-приложение, `node_modules`, результаты сборки,
runtime-артефакты, PNG и ICO. Точное покрытие находится в манифесте запуска.
`AGENTS.md`, `SECURITY.md`, `docs/threat-model.md`, `docs/vault-format.md` служат
контекстом; связанный исходник другого модуля можно читать для проверки вызовов.
Агенты не читают отчёты друг друга. У каждого файла только один владелец обзора.

Коды завершения:

- `0`: обзор завершён, подтверждённых Critical/High нет; возможны Medium/Low.
- `1`: ошибка исполнения, структуры, хешей или доказательств.
- `2`: подтверждены Critical/High — релиз заблокирован.
- `3`: неполное покрытие или неразрешённые кандидаты.

Обычные тесты и `npm audit` выполняются координатором отдельно. Их результаты
можно сохранить в `security-check/runs/<id>/checks.md` до объединения. Они не заменяют
проверку исходников. Перед передачей изменений обязательны шесть команд из
`AGENTS.md`. Перед v1 обязателен Codex Security Deep Scan; этот workflow его не заменяет.

## Запуск внутри Codex с нативными агентами

Координатор использует те же манифест, промпты и схему. После подготовки он
создаёт по одному агенту на модуль с `fork_turns: "none"`, без истории основного
диалога и без данных других агентов. При трёх слотах модули идут партиями.
Каждому агенту разрешена запись только собственного JSON в `results/`;
исходники не изменяются. Координатор затем проверяет находки и сохраняет
`integration.json` по схеме. Дополнительный модульный аудит не запускается.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/security-check.ps1 -Mode Prepare -RunId audit-example
python scripts/security-check.py validate --run-id audit-example
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/security-check.ps1 -Mode Merge -RunId audit-example
```

`Prepare` только создаёт задания и не запускает агентов. `Merge` требует готовые
резюме и решения интеграции. Повторная подготовка с существующим ID запрещена;
после изменения исходников нужен новый ID. Ошибка процесса сохраняет результаты
для диагностики и не заменяет предыдущий отчёт фиктивным успешным результатом.
Всегда проверяйте ID и хеш в заголовке отчёта.

Если нативные агенты сослались на `node_modules`, перед `validate` выполните
`python scripts/security-check.py capture-support --run-id audit-example`.
Команда принимает только цитируемые файлы исходников зависимостей внутри репозитория
и три документа контекста: `README.md`, `THIRD-PARTY-NOTICES.md`, `LICENSE`;
до 128 файлов по 8 MiB. Изменение уже зафиксированного supporting source останавливает
запуск. Совпадение строки с реальным поведением по-прежнему проверяет координатор.

## Артефакты и воспроизводимость

В `security-check/runs/<id>/` сохраняются манифест, схемы, отдельные промпты,
JSON каждого модуля, решения интеграции, общий JSON и копия отчёта. Они не содержат
vault-файлов или секретных значений. Копия `report.md` имеет ссылки относительно
корня репозитория; для навигации открывайте корневой `security_check_result.md`.
Тексты находок выводятся как данные с экранированием HTML/Markdown.

Проверки самого workflow:

```powershell
python -m unittest discover -s scripts -p test_security_check.py
```
